# 数据质量与安装身份

## 适用范围

检查电池观察的单位、时间、缺测、重复和安装身份；数据不可比时给出修复或拒判条件。

输入：`installation_id`、`observations`、`units`、`observed_at`。
输入缺失时按缺失流程报告，未知化学体系不猜测；所有比较限于同一安装身份与可追溯测量条件。
本包为 AI 辅助项目合成推理材料，供合成/回放实验使用，不是厂商 SOP、专家签署结论或现场安全规程。

## 证据检查

1. 先比较物理实体、安装身份和观察时间；换新后的序列不能承接旧安装历史。
2. 保留 value=0；只有显式 missing/null 或质量码才表示缺失。
3. 逐字段核对单位和采样频率；先对齐时间再比较通道。
4. 重复上传按观察 ID 与来源指纹去重，重复不是独立确认。

## 候选解释或流程

- **真实状态变化**：支持条件为同安装、同协议且质量合格的独立观察一致；反证/边界为单位、采样时间、映射或缺测尚未排除。
- **采集或传输问题**：支持条件为缺失码、时间错位、重复指纹或通道断续有直接记录；反证/边界为独立仪表支持同一变化且传输完整。
- **协议或身份不匹配**：支持条件为安装 ID、测量条件或单位不同；反证/边界为已验证同实体、同协议且可转换的单位。

## 工具与多轮检查

可调用工具以运行时权限检查为准，本包只声明以下白名单子集：
- `get_asset_context`
- `get_signal_evidence`
- `search_knowledge`
- `rank_tests`
- `append_report`

- 用 get_asset_context 锁定 installation_id，再用 get_signal_evidence 核对原始质量码。
- 仅对未解决且可改变报告的单位/时间/通道问题请求 rank_tests；已经完成的对齐检查不重复。

只读取当前已到达观察；测试结果必须由环境按已选择且已授权测试揭示。未来分支、封存案例、隐藏原因不可检索。
复测失败、超量程、重复上传、矛盾结果、工程师拒绝/无法执行、需要追加授权分别记录，不按轮次自动确认。

## 终止和转交

- 必需单位、时间或安装身份缺失时终止物理根因确认，输出 data_quality_blocked。
- 补正失败、记录互相矛盾或跨安装混合无法拆开时保留 unresolved 并转交数据维护。

## 输出约定

使用运行时报告 schema，将观察事实、数值服务估计、候选、反证、未知项与建议分开；只输出简短可审查理由和可见证据引用。
保留 installation_id、report_version、状态、检查授权与未执行原因。没有校准来源不编故障概率，没有可见测量不填精确数值。
`examples/positive-01.json` 展示适用的证据整理流程；正例不表示物理根因已确认。`examples/insufficient-01.json` 展示初始证据不足的报告。
工作提案不等于正式工单；正式派单必须由人确认。Carbon 工具、因子、碳收益和政策金额不进入诊断报告与 Context。

## 困难反例

- 零电流静置记录不能直接删除为缺测。
- 换新后的正常容量不能作为旧电池报警的假阳性证据。

## 云端合成补充说明

以下仅通过程序格式检查，尚未经过独立专家审查；作为项目合成补充，不是外部专家或文献结论：

- 同一时间戳重复但字段级来源不同，若仅按时戳去重会丢传感器切换记录；需保留来源列并标记冲突。
- 缺失值填充后未回写原始缺失掩码，后续统计会把插补值当实测，需同时保留掩码与填充值。
- 单位混用（如mV与V）在合并表后仍能通过数值范围检查，需按通道单位白名单校验并保留原始单位字段。
