# V2 报告数字词法校验修复

日期：2026-10-02。此记录是独立的 **post-pilot 软件校验修复**。此前实验使用此前冻结的校验器；本修复不修改 V1/V2 冻结 artifact、旧 hash、报告、分数或 Context，不重新运行实验，不调用 LLM。

## 独立复现与原因

只读取报告校验源码，并手工构造中英文字符串。未读取任何 pilot 或 sealed 案例/标签/报告，未使用其数值或分数来选择规则。旧表达式的前后边界使用 Unicode `\w`，包含中文；遇到中文紧邻小数时，完整数字的整数前缀被排除，regex 随后可能从小数点后重新匹配后缀。旧规则还会从 ASCII 标识符和 ISO 时间提取碎片。

| 手工构造文本 | 旧规则提取 | 应有行为 |
| --- | --- | --- |
| `温度18.25` | `25` | 比较完整值 `18.25` |
| `温度-18.25` | `25` | 比较带符号值 `-18.25` |
| `Temperature 18.25` | `18.25` | 比较完整值 `18.25` |
| `sensor_18.25` | `25` | 标识符，非物理数量 |
| `记录2026-09-01T12:30:00Z` | `30` | 日期时间，非物理数量 |

这证明的是一般词法缺陷；没有据此认定某份实验报告的具体失败原因，也没有把未证实的舍入猜测写成事实。

## 实际改动

`battery_platform/app/agent/contracts.py` 增加完整数字扫描器，先整体匹配带符号、小数或科学记数的 token，再过滤边界。这样不会在整 token 被拒绝后重新把小数后缀当作另一数字。中文可直接邻接数字；`18.25V` 等明确紧邻单位、ASCII/Unicode 负号和 `1.825e-3A` 均保留完整值。

独立只读 review 又用自构造文本确认同类边界遗漏，修复一起纳入：英文句末 `18.25.` 的句点不视为 ID 后缀；`kg/g/mm/m/ohm` 等明确工程单位不隐藏前面的量；连字符范围比较两个端点；逗号千位分组 `1,000` 作为完整 `1000`；指数溢出的非有限物理值明确拒绝，不静默消失。这些规则与用例也没有使用实验报告或标签。

ASCII 标识符/版本碎片和明确 ISO、中文日期及时间被过滤。来源文本和事实 claim 使用同一扫描器；来源的 `id/*_id/*_ids` 字段也不授权物理量断言。其余已有证据引用、来源、安装、时间和概率边界继续执行。

本修复保持严格的字面来源数值比对，没有放宽容差，没有新增舍入、单位换算或派生值授权。文本含义仍需要独立语义审查；该扫描器是词法校验，不是完整自然语言物理事实证明。

## 回归证据

新增 `battery_platform/tests/test_v2_report_numeric_lexing.py` 的 38 项用例全部为手工构造，覆盖：

- 中文/英文、小数、正负号、Unicode 负号、紧邻单位和科学记数的完整来源真值通过。
- 字符串和结构化来源共用相同解析；真实 `18.25` 不能授权捏造的 `19.25` 或后缀 `25`。
- ASCII 标识符、版本、ISO/中文日期和时刻不成为物理数值断言或来源授权。
- 一句话同时包含标识符、时间和两个真实测量时，只比较两个完整测量值。
- 句末英文句点、工程单位、范围双端点、千位分组与非有限指数，真值通过、伪造/溢出值拒绝。

实际命令：

```sh
.venv/bin/python -m pytest battery_platform/tests/test_v2_report_numeric_lexing.py \
  battery_platform/tests/test_v2_agent_core.py \
  battery_platform/tests/test_v2_gepa_service.py \
  battery_platform/tests/test_v2_llm_accounting.py \
  battery_platform/tests/test_v2_gepa_workflow.py -q
```

最终实际结果：**95 passed in 11.95s**，其中新增数字词法回归 38 项，已有必要组合 57 项（边界复查前为 83 passed in 11.15s）。没有新增云端请求；没有 sealed 重评分。工程修复与冻结实验的原始结论分别保留，后续实验若采用新校验器必须另行冻结其版本。
