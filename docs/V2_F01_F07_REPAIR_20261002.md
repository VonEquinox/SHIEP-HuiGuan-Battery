## F01：温度缺失与真实 0°C 区分

### 修改链路

`model_lab/modeling/v2/features.py` 的 `segment_view` 增加第六通道 `temperature_valid`。前五通道保持电压、电流、温度、相对时间和阶段顺序；缺温的数值填补为 0，同时有效性为 0；真实测得的 0°C 有效性为 1。点级 mask 表示 V/I/time 曲线是否可用，温度有效性单独表示，避免让可用电压、电流随缺温一起丢失。

短温度数组保留已知部分，尾部缺失；局部 NaN、无穷值和整列 NaN 为无效温度。重采样只在连续有限温度区间内插值，不跨越缺失间隙。`statistical_view` 的温度均值与标准差只使用有效温度；温度缺失 flag 为 1 表示部分或全部缺失，真实完整 0°C 的 flag 为 0。

训练预处理的序列温度均值、标准差只从训练集的有效温度拟合，温度有效性保持 0/1；缺温在标准化后仍为中性填补 0。部分观测的统计保留合格值，只有末段完全缺温的统计被置为中性。`temperature_stat_domains` 明确哪些 domain 的第 6/7 统计字段是温度，避免将 DYAD 原生电压统计当成温度处理。

联动修改包括 `contracts.py`、`lifetime_features.py`、`prediction.py`、训练入口和平台按包输入适配器。新 schema 为 `battery_features_v2_channel_validity_1`，前缀数据版本为 `v2-prefix-channel-validity-2`。旧 `battery_features_v2` 和五通道模型继续绑定其原始输入；新旧 schema 不匹配时返回 unsupported，不能只替换输入而沿用旧模型指标。已有前缀特征目录拒绝覆写，混合不同 schema 的来源包也拒绝合并。

独立审阅额外发现，省略温度统计 domain 元数据会绕开部分标准化规则；现已在特征载入及模型包构造前严格校验该字段，缺失、错误类型、重复、越界、不完整或误包含 DYAD 均被拒绝。

## F02：数值友好的原文 span 抽取

`battery_platform/app/agent/feedback.py` 用数值友好的边界扫描代替把每个英文句号都当作句尾的正则。保留小数、前导小数、负号、科学记数、范围和点分日期；普通英文句尾和中文句尾仍可切分。每条自由文本事实满足 `free_text[start:end] == source_text == claim`，不重写数值或单位。

用户复现 `本次内阻为12.4 mΩ，复测电压为3.65 V。` 现在保持完整一条事实。抽取版本为 `span-extractor-v2-numeric`，结构化测量保留 `source_field/source_index`。这是反馈事实提取修复；不将历史报告引用校验器的词法修复重复计为新发现。

## F03：完整事实保存，有限 Context 按语义投影

每个 Memory 保存完整 `fact_references`：原 claim、原文 span、来源字段/下标、反馈 ID/版本、可见时间、信任等级和稳定引用 ID。ADD、REVISE、CONFLICT、快照持久化及严格回归验证均接受并保留这些字段。修订保留既有事实，冲突保留两侧来源，不把反证静默变成已确认结论。

面向模型的投影仍限制 6 条事实、2,400 个 claim 字符，但排序改为纠错、测量、反证、未知项、结论、普通描述；同优先级优先晚到事实。按需 `search_memory` 时，相关事实优先进入投影。省略数量和检索入口明确记录；超长事实只展示有标记的原文节选，完整来源仍留在快照。

独立检索索引完整事实和冲突，而非仅检索有限摘要。同一 Memory 在初始 Context 已占用预算后，工具可以返回同一版本的另一组相关事实；不增加唯一 Memory 数、不替换成新的 Memory 修订。这修复了“保存了末尾测量，但模型仍无法取出”的联动问题。反馈事实人工纠正 API 同步支持服务器生成的结构化来源坐标。

测试覆盖结论末尾、测量末尾、晚到反证、文字与结构化测量冲突、低信任测量、超长事实、持久化重载、初始摘要之后按需检索和引用篡改。文字与结构化值冲突时保留两个原值及其信任等级，不自动选择一个作为真实值。

审阅还发现真实 `feedback_compute` 会将自动抽取结果传回旧人工纠正预算，导致合法长句或超过 100 条自动事实被拒绝。现通过与原文自动抽取结果逐字段比对识别这一途径，仅允许既有信任降级；自动事实遵守原文 20,000 字预算，人工纠正仍保留 100 条/单条 2,000 字限制。3,001 字长句和 110 句普通描述后的测量均通过真实 compute 路径验收。

## F04：GEPA 来源预留、终结和恢复

消费身份由根事件升级为 `(root_id, feedback_id, feedback_version)`。入队记录固定来源版本，执行前和完成时校验版本；旧任务不能读到后来修改的反馈。

| 作业情况 | 来源状态 | 后续行为 |
| --- | --- | --- |
| queued/running | reserved | 同版本不重复入队 |
| 正式评估/终结 | consumed | 同版本不再次自动消费 |
| 临时 provider 失败、失败作业、版本 CAS 冲突 | retryable | 有界退避后恢复 |
| 缺 Key | deferred | 配置签名变化后才恢复，不每轮重复制造任务 |
| 主动取消 | cancelled | 自动调度不恢复 |
| 重启中断 | interrupted | 自动调度不恢复 |

同一来源版本、同一恢复代最多 3 次自动尝试，持久化退避为 60/120 秒，上限 300 秒。新任务幂等身份包含来源版本、前次任务和恢复代；不能因旧根事件幂等键重新拿回失败任务。

新增 `POST /api/v2/evolution/runs/{id}/retry`：管理员或任务所有者 researcher 可显式恢复终态任务，要求 `Idempotency-Key`。缺 Key 返回 503；活动任务或已终结消费的新反馈返回 409。显式恢复建立新恢复代，同时保留旧作业、实际 token/请求数、预算及取消记录。取消和重启恢复必须通过该显式入口表达新意图。

回归使用隔离数据库及离线 provider 合同客户端，覆盖暂时失败、无 Key、Context CAS、反馈改版、完成时来源变化、取消、重启、重复恢复和新版已消费后的拒绝恢复。executor 捕获临时错误而仍产生评分记录时，未建立有效 baseline 的失败可重试；安全/权限拒绝仍保持终结。token 和请求数断言用于验收费记录保留，不将离线客户端数字冒称真实云端账单。完整 API 与协议见 [GEPA_RECOVERY.md](../battery_platform/docs/GEPA_RECOVERY.md)。

## F05：无 Memory 对照在执行层关闭检索

`ReplayEvaluator.evaluate` 和 `replay_session` 对 A0/A1 采用明确的 `memory_enabled=false` 执行政策，冻结到实验配置。执行快照清除 Memory 和包含其内容的 changes；隔离 Store，保留同一静态 Skill、授权知识、数值预测和可编辑 Skill 覆盖。

`AgentExecutor` 同步屏蔽初始历史、相似经验和 `search_memory`。禁用门槛在外部 tools 合并后生效，外部 callback 不能重新打开该工具。每次运行记录实际 `initial_memory_ids`、`history_memory_ids`、`tool_memory_ids`、`memory_ids` 和政策状态。

回归中加入可识别经验：有 Memory 对照能够检索，无 Memory 对照初始与工具 ID 均为空；覆盖完整 API compute、外部工具注入和多轮回放。

旧实验若以非空活动 Context 运行原 `no_memory`，其“已关闭 Memory”的对照解释不成立。旧结果文件没有被改分；本轮没有重跑全部云端 A0–A4，也没有将软件回归当作 Agent 准确率上升证据。

## F06：指标契约贯通 scorer、API 与图表

新增严格 `ExperimentMetrics` 契约 `experiment-metrics.v1`。真实字段为 `grounded_assertion_ratio`、`diagnosis_accuracy`、`false_alarms`、`misses` 等；计数保持计数。误报率使用独立标注无需检查根事件数，漏报率使用独立标注需检查根事件数，缺少或为零的分母输出 null/unsupported。

scorer 聚合记录报告事实数、已评估根事件数和独立标注正/负根事件分母。API 完成回调验证契约，列表与详情一起提供契约目录、实际测量、unsupported 原因和实验协议。前端使用服务器目录生成指标选项，展示计数/比例/平均项数及分母，不把 `false_alarms` 改名成 rate。

普通 ReplayEvaluator 没有综合 `score`，前端明确显示 unsupported。GEPA 的选择分数有不同协议，不拼接到普通回放曲线。曲线按照协议、split、方法、来源、案例集、实际执行模式/模型和指标版本分组，避免混合不同方法或规则回退与云端实验。

新增实际 scorer → API 完成 → 列表回归，以及真实隔离服务的浏览器实验：通过真实 POST 入队、worker 运行、GET 列表、界面曲线和分母展示验收。该浏览器用例不拦截 API、不手填期望指标；无云 Key 时执行的是明确标注的规则模式。前端受控响应合同测试作为另一类证据单独保留。

## F07：相似经验的相关性与事件历史分开

`ContextStore.search` 使用确定性词项门槛：中文连续词的双字片段、英文词边界和有限中英症状映射。零相关候选在正反例配额之前被排除；空查询、无关中文、仅数字和通用巡检描述返回空相似经验。结果保存实际命中词项、相关性分数和 `lexical_query_coverage_v1` 政策。

新增 `history()`，明确获取同安装/本根事件已记录历史，标记为 `event_history`。执行器只有在根身份已知时主动加入该历史，并与相似检索、工具共享同一轮 6 个唯一 Memory 的预算；`no_memory` 同时关闭两者。正反例各最多 3 条，只在相关且适用的候选中平衡。

真实 API 由服务器绑定当前 `session:*` 以及该会话在 cutoff 前已有的 `order:*`，使派单前会话反馈和派单后工单反馈可以作为同事件历史。不会把同安装其他会话、其他工单或未来批准当作历史。这个服务接入补齐通过原工作流和新的隔离用例验收。

该实现是可复现的词项检索，不声称已建立嵌入语义检索或获得“相似案例准确率”的云端质量提升。
