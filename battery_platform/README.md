# 慧管电池 · 独立健康与运维平台

这是从零创建的新应用，目录为 `battery_platform/`。不读取、复制或迁移旧业务前后端、旧数据库或旧口令；只复用 `model_lab/` 中已经形成的模型、特征契约、数据版本与研究报告。

原项目的源程序、需求文档和设计说明书保存在 GitHub 的 `original` 分支；当前 `main` 分支只保留 V1 重构基线。

**产品边界：真实实验数据和真实模型计算，加上明确标注的模拟资产/人员，以及真实持久化的运维流程。** 不是已接入生产设备的 BMS/EMS，不下发物理停机、换模或控制指令。

## 1. 在当前电脑上启动

依赖和前端生产构建已经在交付过程中安装、验证。项目主运行数据库没有预置默认管理员密码，也没有把自动化测试账户放入主数据库。

```bash
cd /Users/vonequinox/Program/GithubProjects/SHIEP-HuiGuan-Battery/battery_platform

./manage.sh bootstrap     # 首次使用：设置管理员密码，至少12字符
./manage.sh demo          # 建立模拟资产、注册冻结模型、创建演示角色
./manage.sh serve         # 单进程、仅绑定127.0.0.1:8787
```

打开 `http://127.0.0.1:8787`，使用刚创建的管理员账户登录。`demo` 对新建演示账户生成随机口令，并只在该次终端输出；它不会为已有用户重置口令。遗漏口令时，管理员可以在系统管理中重置。

首次演示按页面执行：

1. 总览 → “导入 XJTU 开发数据”，等待导入任务完成。
2. 数据中心 → “批量绑定演示槽位”。绑定表示实验记录回放，不表示实验电芯就是真实现场设备。
3. 模型中心 → 明确选择快速 ExtraTrees 或完整混合模型 → 选择源电芯 → 提交推理。
4. 健康中心核查预测、数据适用范围和证据；告警中心生成工单。
5. 调度员选择符合技能、值班和负载约束的维修人员；维修人员接单、开始处理、上传证据、提交结果；另一位调度或管理员验收、关闭。

实际预测未达到演示维护阈值时不会造告警。需要稳定复现特定业务情景，可使用“注入独立演示场景”；这些事件会明确标为合成数据，并且不会写成模型预测或计入精度。

## 2. 新环境安装与命令

实测环境为 macOS、Python 3.12、Node 26。Python 与 JavaScript 依赖分别固定在 `requirements.lock` 和 `frontend/package-lock.json`。

```bash
./manage.sh setup              # 安装新应用独立依赖，初始化表结构
./manage.sh build              # TypeScript检查 + 生产构建
./manage.sh bootstrap          # 不会覆盖已有用户
./manage.sh user researcher --name 算法研究员 --role researcher
./manage.sh demo
./manage.sh serve

./manage.sh test               # 隔离数据库的后端测试
./manage.sh browsers           # 可选：下载验收专用Chromium到本目录
./manage.sh e2e                # 浏览器验收，临时独立运行目录与8791端口
./manage.sh verify-models      # 实际导入、训练、ET/混合推理和重启验收
./manage.sh status
```

可配置 `BATTERY_PORT`（默认8787）、`BATTERY_RUNTIME`（默认本目录runtime）、`BATTERY_ML_PYTHON`（默认兄弟目录model_lab/.venv/bin/python）。开发模式用两个终端运行 `./manage.sh serve` 和 `./manage.sh dev`，后者位于5173端口并同源代理 `/api`。

不能通过多开 API worker 增加模型并行度；本版是单机单业务服务。服务进程使用运行目录锁，计算子进程另有全应用计算锁。部署命令固定为一个 worker。

## 3. 已实现的工作区

| 工作区 | 实际功能 |
|---|---|
| 总览 | DB派生的资产、覆盖率、告警、工单、任务及审计；初始化引导；无随机图表 |
| 资产中心 | 站点→柜→模组→电芯；创建/编辑/退役；固定坐标示意；安装身份与更换；显式回放绑定；下钻历史；柜/模组覆盖和低健康电芯证据 |
| 数据中心 | 实际XJTU开发数据导入；哈希/来源/质量；按电芯分页；71维观测和标签；CSV导入/导出；引用中的版本禁止删除 |
| 模型中心 | 原模型注册；快速/混合分支明确区分；真实ET训练；按电芯验证；同样本评估对比；任务队列/日志/取消/失败；版本停用和血缘 |
| 健康中心 | 原始预测与输入快照；模型版本；训练范围出界诊断；两分支差异；策略版本；持续性/冷却/去重；追加反馈 |
| 告警与工单 | 告警确认/解除/重开；幂等建单；人员资格与距离负载排序；接单/处理/证据/独立验收/关闭/退回/重开/取消；通知和历史 |
| 系统管理 | 五类服务端角色；账户启停和密码重置；最后管理员保护；会话撤销；审计筛选；站内通知 |

**角色：** 管理员、算法研究员、调度员、维修人员、观察员。维修人员只能处理获派工单，不能验收自己的结果；观察员不能通过直接调用接口绕过页面权限。

## 4. 数据与模型事实

XJTU导入读取既有验证特征视图，实际导入 **2058行、21个开发电芯**。原视图的三个保护电芯及其346行不会导入或评分。源行身份保留为 `xjtu-view-row-*`；不把它伪称为真实物理循环数。

支持的模型输入是当前和参考各71维，加上可观测局部电量对数比。它要求 **3.7–4.1V 部分恒流充电窗口和初始参考**，不是随便输入几项BMS电压/温度就能使用的通用模型。

冻结快速模型、冻结混合模型均来自既有研究产物。原始研究代码和权重只读；完整混合模型保留全部2058行上下文、三个种子、每种子八个视图。重型计算在单独子进程运行，MPS高/低水位为0.7/0.5，未取消内存限制。

历史开发分数是研究记录，不是平台新产生的独立测试成绩。冻结模型在已导入开发电芯上训练过，因此平台会将这种评估标为“含训练电芯”。新建平台训练任务按物理电芯划分训练/验证集，只在训练数据拟合标准化；原始保护测试集仍不可用。

模型不提供RUL、热失控概率、认证安全风险或生产控制建议。特征出界比例和分支分歧不是校准置信度。CSV上传只能核查声明的格式/数值，不能证明上传者没有给同一个物理电芯起不同名字；此类数据始终带“来源待核验”标记，不自动触发实验诊断。

## 5. 实验、仿真、反馈分别留痕

- `experimental`：可追溯实验数据；`experimental_replay`：真实预测在明确绑定的模拟槽位回放。
- `simulated`：虚拟站点、人员、位置和注入场景；不会计入模型测试精度。
- `declared_unverified`：用户上传、尚未独立核实的特征来源。
- `measured_declared`：反馈者声明的实测值，仍需独立复核。模拟或声明反馈均不自动进入训练数据。

关闭工单不会把SOH改成100%，也不会自动解除原告警。登记电芯更换会创建新安装身份、清空回放绑定并保留旧预测/旧工单。已有预测历史的安装身份不能直接改绑另一个源电芯。

## 6. 备份、恢复和停止

使用Ctrl+C正常停止服务；监督器会结束自己的计算子进程。异常重启将遗留running任务标为interrupted，不会自动重放已可能执行过的任务。子进程有父进程存活监测和共享计算锁。

备份必须先停止服务，程序会检查运行锁。备份包含数据库、附件、平台训练权重与任务文件，并为每个文件记录SHA256；它含有私人业务记录与账户哈希，须自行保护。

```bash
./manage.sh backup
./manage.sh restore runtime/backups/backup-时间戳 runtime/restored-v1
BATTERY_RUNTIME="$PWD/runtime/restored-v1" ./manage.sh serve
```

恢复只写入不存在的新目录，拒绝覆盖当前库；校验文件和SQLite完整性；重定位平台模型路径、撤销会话、将未完成任务标为中断。`model_lab/`原模型数据不包含在应用备份中，需要单独保留。
