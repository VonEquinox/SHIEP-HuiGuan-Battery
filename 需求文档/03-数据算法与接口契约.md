# 数据、算法与接口契约

本契约先定义 P0 **实验模型链路**，再说明 P1 演示和 P2 生产数据如何隔离。凡来源或单位未证实的字段，都不能猜成物理测量值。

## 1. 数据来源与信任级别

| 数据域 | 当前证据 | 允许用途 | 禁止推断 |
| --- | --- | --- | --- |
| 实验 | 仓库两份相同的 `SeversonBattery.mat`；导入脚本；实验电池 SQL | 训练、离线评估、实验电芯预测与图表 | 不能说是本项目现场柜采集的数据。 |
| 演示 | `bms_edge_computing.py` 模拟值及前端随机/固定值 | UI 联调、流程演示 | 不能进入正式评估指标、生产告警或减排成绩。 |
| 生产 | 当前未见可靠的真实 BMS 接入链路 | 仅作为 P2 待建数据域 | 不能用实验或演示样本代填。 |

文件名、124 组电池数量与标签结构提示 `.mat` 是公开 Severson 数据的加工版，但仓库没有可复现的原始数据到该文件的转换脚本。记录哈希和可能的上游来源，不把“推测出处”写成经验证的数据血缘。MySQL 实验表是文件导入后的副本。

## 2. P0 对象关系

```text
数据集版本（文件哈希、来源、字段字典、划分）
  ├─ 电池实验单元 ─ 循环样本（特征、PCL、RUL、循环编号）
  ├─ 训练任务 ─ 模型版本（权重、标准化器、标签定义）
  └─ 测试任务 ─ 逐样本预测/真值 ─ 指标报告
模型版本 + 输入样本 ─ 单次预测记录 ─ 可选的真值回填
```

最低标识：数据集版本 ID、电芯 ID、循环编号、划分 ID、训练任务 ID、模型版本 ID、测试任务 ID、预测记录 ID。不能用页面数组下标或虚构柜号连接实验结果。

| 对象 | 最低字段 | 约束 |
| --- | --- | --- |
| 数据集版本 | 源文件名、SHA-256、来源说明、加工脚本/未知标记、字段 schema、导入时间 | 文件变动产生新版本；原版不可无痕覆盖。 |
| 实验电芯 | 原始单元编号、所属数据集、划分、循环数 | 训练/验证/测试按电芯隔离，不按循环随机混切。 |
| 循环样本 | 电芯、循环编号、特征向量、PCL/RUL 标签、缺失/异常标记 | 特征列位置、单位与变换规则必须与模型一致；未经证实不冠以电压/SOC 等名称。 |
| 训练任务 | 数据/划分版本、算法、参数、种子、状态、日志、开始结束时间 | 失败及取消可查；任务完成不代表模型合格。 |
| 模型版本 | 目标、特征 schema、权重路径与哈希、标准化器、训练任务、指标 | 权重缺失或输入不兼容时不可推理；结果指向不可变版本。 |
| 测试任务 | 模型、保留测试集、逐样本真值/预测、指标、代码版本 | 测试标签不得进入输入或参数拟合。 |
| 预测记录 | 电芯/循环、输入快照、模型版本、输出、状态、执行时间、真值来源 | 由后端模型计算；真值回填追加记录，不篡改预测。 |

## 3. 特征、目标与单位

- 文件中可见 `Features_mov_Flt`、`Cycles_Flt`、`Num_Cycles_Flt`、`PCL_Flt`、`RUL_Flt` 及训练/测试单元索引。`functions.py` 将特征与循环数拼为输入，将 PCL/RUL 拼为目标；Web 训练代码取目标第 1 列训练 SOH 相关值。**必须核对第 1 列到底是 PCL 还是 SOH 表示法**，再决定转换公式和页面名称。
- 旧导入脚本明确写了“假设特征顺序为 `[voltage,current,temp,capacity,resistance,soc,soh,power]`”。因此 SQL 列名不能充当原始字段字典。P0 在拿到真实字典前用 `feature_0` 等中性名称展示。
- SOH、PCL 的 0~1 与 0~100 表示，RUL 的“循环数”还是其他尺度，都要在数据集版本中定义。未经核对不能把 `SOH = 1 - PCL` 或 `RUL = SOH × 2500` 当作真实预测模型。
- 每份模型记录输入维度、列顺序、缺失处理、标准化均值/方差和目标变换；推理时逐项校验，不允许自动补常数特征。

## 4. 训练、测试与评价

1. 加载 `.mat` 后校验各数组长度、每芯循环数、非有限值、标签范围、划分索引合法性及电芯交集；校验报告与数据版本绑定。
2. 训练集拟合标准化参数，验证集用于选参/早停；测试集只在模型冻结后用于最终评估。若沿用原文件 `train_ind`、`test_ind`、`secondary_test_ind`，明确其在本项目里分别称为训练、验证、测试。
3. Baseline、BiLSTM、DeepHPM 使用同一版本的训练/测试数据比较；记录随机种子、超参数、迭代日志、权重与依赖版本。现有 `.pth` 可作待验证材料，不能仅凭文件存在宣布模型达标。
4. SOH 评价报告至少包括电芯数、循环样本数、MAE、RMSE、R² 及逐电芯分布。指标从保存的真实标签和模型输出重算；没有真值不计算精度。
5. RUL/PCL 若要作为独立预测目标，须分别定义标签、训练输出、误差指标和保留测试集；仅有数据列或页面数字不算实现。
6. 所有报告带模型版本、数据版本、目标定义、样本范围和计算时间。任何声称的 R² 或“准确率”都必须附可复算记录。

## 5. 预测接口行为

P0 推理请求最少包含：实验电芯/样本 ID、数据版本、模型版本。服务端读取并校验特征，返回 `succeeded | insufficient_data | incompatible_model | failed`、预测目标/数值/单位、输入快照、权重版本与时间。输入缺失、权重不存在、维度不符或运行错误都返回对应失败原因；不能保存 `0.887`、`1520` 或前端提交的“预测结果”冒充推理输出。

测试接口返回逐样本结果和聚合指标；图表从该结果渲染。回填实际值需标识来源、测量/标注时间、操作者与修订历史。前端可以保存演示结果，但必须走独立的演示域接口或存储，不与正式预测记录混用。

## 6. P1/P2 扩展边界

P1 大屏、工单、碳计算中出现的数字标注为 `experimental` 或 `simulated`；不能合并统计。碳情景保存输入、公式、因子版本和“非核证估算”状态。P2 的生产数据另建物理设备 ID、采集来源、时间戳、单位与质量状态，只有实际接入与业务验收后才允许触发生产告警/工单。实验模型若转用于 P2，须重新验证设备类型、特征兼容和现场误差。

## 7. 接口与验证要求

已有 `batteries`、`training`、`models`、`prediction`、`model_comparison` 等接口可作实现参考，路径和返回结构以重新确认的 OpenAPI 为准。验收至少覆盖：数据划分无交集、特征顺序一致、训练失败可见、缺权重失败、真实测试指标可复算、前端不得提交预测值跳过推理、演示记录不能进入实验成绩。接口错误应明确返回错误，不用“成功 + 默认值”掩盖。
