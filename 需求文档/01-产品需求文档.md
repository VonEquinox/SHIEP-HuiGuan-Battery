# 慧管电池产品需求文档

状态：接手基线 v0.2。优先级以**目前实际投入的功能和数据**为准；遗留代码只提供证据，不自动满足下面的验收。

## 1. 产品定义与边界

现阶段交付物应定位为**实验电池健康预测与模型评估平台**。主要使用者是算法开发者、实验评估者和查看结果的项目成员。一次完整的核心工作是：识别数据集及其标签 → 按电芯划分训练/验证/测试 → 训练候选模型 → 保存权重与指标 → 在保留测试集上评估 → 选择模型对实验电池预测 → 查看真值、误差和预测记录。

仓库还包含储能柜大屏、电芯预警、工单和减碳页面。这些说明作者有扩展为运维展示系统的意图，但现有输入大多是 Severson 实验数据或模拟值。**不能把实验电池编号映射成真实园区设备，也不能把演示风险、工单和碳数字宣称为实测业务结果。**

## 2. 优先级与实施顺序

| 顺序 | 级别 | 交付主题 | 为什么在这里 |
| --- | --- | --- | --- |
| 1 | P0 | 核实 `SeversonBattery.mat`、字段、标签、划分与授权 | 所有模型结论依赖它；当前加工来源与特征字典不明。 |
| 2 | P0 | 实验数据查询、筛选与可追溯展示 | 后端已有电池/生命周期查询，前端数据管理却生成模拟行。 |
| 3 | P0 | Baseline/BiLSTM/DeepHPM 的训练任务与模型产物 | 后端确有训练流程和多份权重，是当前投入最多的核心能力。 |
| 4 | P0 | 独立测试、指标计算、模型比较与预测记录 | 当前测试页随机生成预测/真值，无法证明模型效果；需要打通真正评估。 |
| 5 | P0 | 最小登录、模型/数据操作权限、任务故障可见性 | 保护实验记录，避免后台不可用时仍显示模拟成功。 |
| 6 | P1 | 大屏、电芯风险、告警与工单的受控演示 | 页面/接口有雏形，但缺真实设备来源和闭环。 |
| 7 | P1 | 减碳情景、资源分享、增强型账号管理 | 有界面或接口，须标明假设和数据域。 |
| 8 | P2 | 真实园区/BMS/现场移动端/生产级运维与核证减碳 | 需要新数据、新流程和业主决策，不属于当前核心的自然完成态。 |

P0 的“已经做到”是**有代码和文件基础**，不是“无需重做”。特别是训练能启动与模型有效是两件事；有预测记录与真实模型推理也是两件事。

## 3. P0 功能需求

| ID | 需求 | 当前基础 | 可验收结果 |
| --- | --- | --- | --- |
| P0-01 | 数据集登记与来源核验 | 两份相同的 `SeversonBattery.mat`、导入脚本和 SQL | 能记录文件哈希、版本、公开原始来源、加工步骤、字段名/形状/单位/标签定义；来源无法确认的字段标为“未核实”。 |
| P0-02 | 数据结构与质量检查 | `.mat` 中有特征、循环、PCL、RUL、划分索引 | 校验电芯数、每芯循环数、数组对齐、缺失/异常值、训练/测试电芯交集；错误可见且阻止不可信训练。 |
| P0-03 | 实验电池和循环数据浏览 | `battery_info`、`battery_lifecycle_data` 查询接口 | 按电芯、划分、循环范围分页查看实际导入记录；展示来源与单位；图表取相同记录，不能临时随机生成。 |
| P0-04 | 候选模型训练 | 后端 `training.py` 包含 Baseline/BiLSTM/DeepHPM 训练 | 选择算法和合法参数，能启动、查看日志/状态、失败原因、验证曲线和最终产物；同配置、数据版本与随机种子可复现。 |
| P0-05 | 模型登记与版本管理 | 训练后保存 `.pth`、模型接口 | 每份模型绑定数据哈希、标签、输入特征顺序、标准化器、代码版本、参数与评估结果；损坏/缺失权重不伪装为可用。 |
| P0-06 | 独立测试与模型比较 | 测试页、比较页及部分后端接口 | 测试数据与训练电芯不重叠；逐样本展示预测和真值，计算 MAE/RMSE/R² 等有分母的指标；同一测试集可比较模型。 |
| P0-07 | 实验预测与结果留档 | 预测接口、记录表、实际值回填接口 | 预测只能由所选模型对兼容的实验特征计算；记录输入快照、模型版本和时间；失败显示原因，不写固定/随机兜底值。 |
| P0-08 | 结果分析与真值回填 | 结果分析页、`actual-value` 接口 | 曲线和统计只来自已保存测试或预测记录；回填需来源和测量时间，原预测不被覆盖；无真值不显示“精度”。 |
| P0-09 | 最小身份与错误状态 | 登录和用户接口已有 | 登录后可访问授权实验资源；停止硬编码口令绕过；接口故障、无数据、训练失败有明确状态。 |

### P0 关键验收流程

1. 从已登记的 `.mat` 或确认过的数据库快照选取实验数据，显示数据来源、字段字典和训练/验证/测试电芯数；对无法证实物理含义的列，不显示成“电压”等实测量。
2. 选择一个候选算法训练，任务状态和日志与实际执行一致，模型文件和标准化参数可定位；同样输入可重复计算出容差内结果。
3. 选择未参与训练的测试电芯，生成逐循环预测与真实标签对照；指标由这些记录计算，重进页面数值不变。
4. 故意移走权重或提供不兼容特征，预测返回失败且不写成功记录；模拟测试值绝不进入正式评估。
5. 对有来源的实际标签执行回填，保留原预测，重新计算误差并能追溯是谁、何时、根据什么改了真值。

## 4. P1 扩展需求：有原型，但不得冒充生产系统

| ID | 模块 | 应做的事 | 启用条件与限制 |
| --- | --- | --- | --- |
| P1-01 | 仪表板 | 汇总实验电池数量、模型、预测和训练状态；演示柜图可单独切换 | 实验统计来自数据库；虚构园区/柜必须显著标“模拟”，不可混入实验指标。 |
| P1-02 | 电芯风险演示 | 用明确规则把**实验预测**映射为研究性等级并展示依据 | 不称为现场预警；阈值只作可配置演示，不能指导设备安全操作。 |
| P1-03 | 演示告警与工单 | 从演示事件创建、查看和变更状态，展示工作流程 | 只在演示域运行；工单若保留必须以服务端为事实源，随机工程师/本地照片不能当真实派单。 |
| P1-04 | 减碳情景计算 | 输入假设与因子，输出可复算的情景结果 | 标记为“估算/情景”，列出公式和参数；不能宣称实际减排或可交易碳资产。 |
| P1-05 | 分享与管理 | 分享实验模型/数据、管理成员可见范围 | 权限必须在服务端执行；不把页面隐藏等同于授权。 |

P1 不是 P0 的上线前置条件。若时间不足，优先保留清晰标注的演示壳，不得以随机页面掩盖 P0 链路缺失。

## 5. P2 候选新业务

只有在业务方明确要求并提供真实接入条件后，才把以下内容立项：真实 BMS 协议及设备身份、园区/柜/模组/电芯资产树、实测时间线与质量规则、经批准的告警阈值、工单派发/到场/处置/验收、移动端、通知、跨园区权限、真实运维绩效、可核证碳核算。它们不能从实验数据自动“升级”出来。

## 6. 非功能要求

- **数据可信**：每条统计和曲线标明实验、模拟或生产来源；实验数据不得伪装现场数据。无数据、无真值、无模型时显示未知/失败。
- **可复现**：锁定数据哈希、电芯划分、特征与标签定义、标准化参数、种子、代码和权重版本；测试集不参与拟合和调参。
- **指标可解释**：注明 SOH/PCL/RUL 的定义、单位、样本数和评价范围。RUL/PCL 列存在不等于模型已验证预测它们。
- **基本安全**：移除固定口令及默认明文密钥，模型文件和实验数据操作有服务端权限与操作记录。
- **可维护**：训练任务、数据库迁移、权重文件、日志和失败状态可部署与恢复；具体性能 SLA 需实测后确定。

## 7. 交付清单

P0 交付为可运行的实验平台、数据来源与字段字典、训练/测试划分记录、模型版本清单、独立测试报告、预测结果追溯、部署与最小验收记录。P1/P2 的页面或概念不得代替这些证据。
