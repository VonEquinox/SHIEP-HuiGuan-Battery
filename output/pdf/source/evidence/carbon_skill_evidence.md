## Carbon：用户现在能操作和看到什么

“碳与经济”中心提供以下完整操作链。

1. **登记排放因子**：管理员填写因子代码、版本、数值、单位、气体口径（kgCO2 / kgCO2e）、边界、地区、来源 URL/标题、有效期、偏差与共享不确定来源。界面同时标注真实/待核验/合成来源；新建因子初始仍为待核验。
2. **配置共同服务情景**：声明比较对象共同交付多少 kWh、期间、功能边界、终端处理和基准方案；录入继续使用、检查、维修、换模块/换包等有限候选，以及活动、状态和价格假设。
3. **运行异步求解**：设置 Γ 不确定预算，查看真实作业状态，可以取消。重算期间保留上一次冻结结果并标注旧 Γ 和输入版本，避免把旧结果误当新结果。
4. **读取结果表**：每个候选显示可行性、名义碳排放、碳参数集上下界、人民币成本/上下界、相对基准的比较减排、内部碳影子估值，以及有证据资格的现金收入。
5. **解释每个数字**：点开候选，查看逐期活动量、单位、排放量、来源因子与版本、寿命/效率状态、终端状态、政策资格、成本分解和不可行原因。
6. **比较决策**：成本—碳 Pareto 图用圆点表示名义值、方点表示当前 Γ 上界；分别展示名义/鲁棒前沿，以及 ε 约束解、Γ 扫描和单来源敏感性切换点。
7. **形成可追溯台账**：输入记账依据和核算期间，将冻结可行结果追加为待审核条目。原条目不删除，纠错使用冲销关联条目；演示导出和正式导出分开。

这是一项独立数学决策功能。运维 Agent 的自然语言、Skills、Memory 或所谓诊断置信度不能直接改写碳因子、寿命假设、政策资格和台账数字。

## Carbon 为什么这样建模

要回答的是“在**同样服务量**下，继续使用旧电池、检修或更换的排放与成本如何变化”，单独计算制造减排会遗漏旧电池低效率带来的更多用电，也可能把延期更换错误地说成永久免除制造。为此实现包含四层模型。

### 第一层：活动核算与边界一致

基本式为 `E = Σ(a_i × f_i)`，其中 `a_i` 是活动量，`f_i` 为对应版本排放因子，结果为 kg 气体。用电按 kWh、制造按电池块数或额定容量、运输按吨公里、检查按次数等明确单位计算。求解器拒绝来源缺失、单位不合、CO2 与 CO2e 混合、年度运行边界与全生命周期边界混合。

同服务量比较收益为 `B = E_baseline − E_candidate`。负 B 表示候选排放更高，按原值展示。物理排放不进行货币折现。期末状态必须有共同处理定义，否则不能据两个不同剩余价值的方案宣称公平比较。

### 第二层：寿命、效率与更换的状态递推

有限状态 `s` 包含可用性、效率 η、年龄、健康状态和旧/新安装 cohort。以 `p_(t+1) = p_t P_t` 精确传播分布；每行转移概率与每期分布都必须和为 1。

同一期需要输出 `D_t` 时，输入电量使用 `Σ_s p_t(s) × D_t / η_s`，即 `E[D/η]`；不能使用 `D/E[η]`，因为逆效率是非线性的。不可用状态单独计未满足服务，或按明确备用效率计补充用电。辅助能耗只有在效率口径尚未包含时额外加入。

更换边必须进入独立的新电池年龄 0 分布，并显式计制造活动；正常老化不能把旧安装改写成新安装，检查本身不能提升物理健康。旧电池剩余寿命分布 R 与新电池寿命分布 L 使用独立 renewal recursion 计算期望更换次数，右删失终点只表示寿命下界。

**适用边界**：当前 SOH 预测不能自动变成已验证的寿命/效率转移模型。运行时会拒绝尚未建立的 `validated_model` 适配输入。明确测量或用户情景状态可用于情景分析；普通实测电量核算无需寿命 ML。论文/PDF 应将它称为“已实现的状态核算方法”，不能称为“经真实设备验证的寿命碳模型”。

### 第三层：预算鲁棒性与共享误差

固定活动清单下因子误差按仿射形式表达：`E(z) = E_0 + Σ c_j z_j`，并限制 `|z_j| ≤ 1, Σ |z_j| ≤ Γ`。支持函数把绝对系数排序，取前 `floor(Γ)` 项及下一项的 Γ 小数比例；得到 `E_0 ± h_Γ(c)`。这是指定误差集合的范围，不是统计置信区间，Γ 不对应 95% 置信度。

比较时先对同一个来源维度求差：`c_B = c_baseline − c_candidate`，再对 B 求鲁棒区间。同源电网因子可抵消；没有把“基准上界减候选下界”当成严格比较收益。只有收益下界大于 0，才显示在定义参数集内始终更优。

当前精确性限于固定活动清单和仿射系数；效率/状态转移不确定性要显式单列情景，不能偷偷纳入 Γ。候选采用有限枚举，尚不是整数模块组合优化器；敏感性一次改变一项来源，其余取名义值，并有工作预算上限。

### 第四层：经济决策与可审计记账

运营 NPV 为初始成本加各期能源、检查、人工、更换、停机和其他成本的折现和；合格政策现金单列后扣除。影子价值为 `B(kg)/1000 × 内部碳价(RMB/t)`，标签明确是内部情景估值。

政策规则要检查地区、实体、时间、技术条件、材料、合同/交易依据及已结算收款证据；缺证据不产生可兑现收入。同一交易不得重复建立收益，项目 cap 跨各期合计约束。正式导出排除合成、待核验、预测、未审、无效冲销和重复实测来源。该导出也不表示第三方核证或碳信用签发。

## 约束排程：由人批准的可执行计划

输入只来自正式创建且未分配工单。每任务分配一个合格工程师或进入未分配集合；检查活跃账号、technician角色、值班、技能与资格。任务连续落在合法班次，`NoOverlap` 防止工程师重叠；`AddCumulative` 约束工具容量和可用时段；前置任务要已验收/关闭或在同草案先结束。旅行使用显式分钟矩阵，包括初始位置到首任务及相邻任务，不从经纬度猜可达性；缺路不可通行。

服务与旅行合计工时、任务数上限、硬截止均为硬约束。已确认未完成任务成为锁定区间；未知安排不会被猜为空闲。输入和版本 fingerprint 发生变化，旧结果标为 STALE，不能覆盖已现场接单。草案可人工编辑，但重新核验全部硬约束且不再宣称求解最优；最终由管理员/调度员确认才原子派单、通知并写审计。

求解依次优化：critical漏派数、critical逾期分钟、high漏派数、high逾期分钟、routine漏派数、routine逾期分钟、旅行分钟、人员总工作分钟差。每阶段证明最优才固定该目标进入下一阶段。未完成全阶段但有可行解返回 feasible；无可行解区分 infeasible/timeout。没有用普通任务数量抵消严重漏派，也没有将 Carbon 收益塞入排程目标。

用户在运维工作区配置资源与要求、创建求解草案，看到作业状态、逐阶段目标、未分配原因、人员甘特与负载，编辑可行计划后人工确认。技术员仍只能看到本人工单。

**数字证据**：40个小窗口fixture的八项目标与独立离散穷举oracle逐一相符，模块17项测试验证真实API权限/事务边界。旅行实例先在A完成T2[0,10]，A→B旅行5分钟，再在B执行T1[15,25]，总旅行5分钟；前置实例T1[0,10]后T2[10,20]；冲突实例两任务都须10分钟内完成，系统保留critical任务、未分配routine任务。这是约束正确性证明，不是对main排程节省百分比、运行速度或大规模全局最优的实测比较。

## 16 个 Skill 完整清单

每个 Skill 都有输入要求、4项证据检查、至少3个带支持/反条件的候选流程、至少2个困难反例、工具白名单子集、停止/转交规则、4个JSON示例、行为检查契约、来源证据和文件hash。作用是让一个运维LLM在不同问题上按需加载可审查流程；这些16项不是16个分别训练的神经网络，也不是16个常驻决策Agent。

| Skill ID | 功能与关键输出 | 防止的误判断 |
|---|---|---|
| data-quality | 先检查单位、时间、缺测、重复、安装身份；不可比时补正/拒判 | 把真实0当缺失、换新后接旧历史、重复上传充当独立证据 |
| chemistry-eligibility | 核对体系、型号、协议、模型版本；区分适用/元数据不足/域外 | 从电压猜化学体系，对不支持协议强行预测 |
| soh-trend | 解释同安装同参考容量的SOH趋势、分布与局部变化 | 把模型估计当实测、早期激活当退化、模型分数当故障概率 |
| lifetime-interpretation | 解释寿命/生存曲线、服务阈值、删失与使用强度 | 末次观察当EOL，无未来使用强度就换算日历寿命 |
| efficiency-measurement | 对齐SOC、完整循环、能量积分及辅助边界，解释效率差异 | 部分循环当往返效率，Ah当Wh，辅助能耗双计 |
| internal-resistance | 对齐SOC/温度/倍率/方法，区分电芯变化、条件差异与连接问题 | DC脉冲与AC阻抗混比、固定万能阈值、凭空危险操作 |

## Skills 和数据是如何合成与验证的

生成器按规范目录生成16个包，每包包括 `SKILL.md`、manifest、`references/evidence.md`、`checks/contract.json` 和4份example。frontmatter仅name/description；自定义字段在manifest。包级通用流程不把某条合成案例的数字阈值推广成真实厂家阈值。

示例只投影cold_start当前可见字段：资产、安装身份、初始观察、测试目录及真实存在的同期群体信息。hidden_truth、expected_behavior、未来测试/反馈、观测似然和oracle均不可进入示例；非cold_start或晚于cutoff的观察直接拒绝。示例正例表示整理证据流程适用，不表示根因已确认；候选confidence留空，初始状态insufficient_evidence。

云端真实合成分为16次Skill补充（各3条条件/反例，共48条）和12次主桶自由工程师反馈（各6段，共72段）；28次HTTP请求全部通过语言结构校验。冻结manifest记录model/base URL、请求/响应hash、usage、状态和未专家审查。Token合计prompt6,280、completion39,128、total45,408。API只提供语言变体和补充措辞，根因配置、物理简化值、split、VOI/排程/Carbon答案由程序确定，不由同一LLM同时生成答案和裁判。没有取得账单，不推测金额。

内容版本含2,400个根情景，12主桶各200；cold_start960、evolution720（6轮各120）、dev360、sealed_test360。另含31,200授权观察分支、33,600parentage记录、17知识证据、40派单/30碳fixture、7类泄漏/越权探针。母模板、物理对象、安装与近重复组整体划分，不跨split；生成recipe仍共享，不能宣称独立真实故障机制测试。

公开部署仅复制许可通过的Skills、知识和cold_start可见资料；oracle、未来分支、evolution/dev/sealed、数学fixture不进入Agent公共索引。生成数据全部带合成来源，无法通过改标签成为真实现场测量。

验证包括16/16标准Skill格式、64示例引用和可见性、白名单/禁止Carbon工具/人确认派单、隐藏字段哨兵不泄漏、未来/sealed拒绝、split/parentage/hash、反馈到达、重复测试幂等与内容测试。冻结生成报告为validation=passed、hashes_checked=true；历史内容阶段82项测试通过。**程序契约正确不等于诊断性能0.9**；Skill/Memory/自进化的有效性应引用总报告的同协议云端对照数值，不拿这16/16冒充模型准确率，也未完成独立专业盲评。

## 云端接口与 UV 一键运行

运行时 `OpenAICompatibleClient` 支持配置base URL/model，POST `{base_url}/chat/completions`，标准messages、tools、response_format=json_object和Bearer鉴权；支持超时、有限重试、实际请求/失败/token记录及usage未知状态。DeepSeek deepseek-flash为已测试云端提供商；凭据仅环境变量，不进入run artifacts。默认外网代理为 `http://127.0.0.1:7897`。

`./scripts/v2.sh install` 使用 `uv sync --frozen --python 3.12`、npm ci/build与DB初始化；后续bootstrap设置管理员、demo建立明确合成演示资产、serve默认绑定127.0.0.1:8787。test会显式清空云Key，提供backup/restore与status。可离线使用冻结cloud enrichment重建内容，避免再次消耗云额度。GitHub保留pyproject.toml、uv.lock和脚本，形成一键可重建环境。
